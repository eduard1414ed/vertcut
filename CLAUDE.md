# CLAUDE.md — как устроен vertcut

Этот файл — для того, кто меняет код: для разработчика и для
ИИ-помощника (Claude Code читает его в начале каждой работы). Тому,
кто хочет просто резать ролики, — `README.md`.

Сервис режет длинные видео на вертикальные ролики с субтитрами.
Замысел — в `private/PUBLIC_SPEC.md`; он не правится. Здесь коротко
то, как оно устроено **сейчас**. Почему именно так — замеры, числа,
истории бед — в `docs/decisions.md`; что делала каждая сессия —
в `private/docs/sessions.md`; отложенное — в `TODO.md`.

Расходишься с этим документом — скажи автору и объясни, молча не меняй.
У каждого правила есть причина: правило без причины через месяц
выглядит произволом и снимается первым. Причина здесь — одной строкой,
целиком — в `docs/decisions.md`.

## Слова

- **Видео** — исходный длинный файл, разбирается один раз.
- **Ролик** (на экране — **clip**) — вертикальный, который из видео получается.
- Как каждое понятие зовётся на экране — `docs/glossary.md`.
- **Кусок** — кусок видео, выбранный `pick`; собранный кусок — ролик.
- **Заслон** — проверка, которая не пускает дальше: сборки (пять
  заслонов в `verify.py`) или автотест, стерегущий правило.
- **Штамп** — запись в файле, что стадия сделана и из чего; по нему
  стадию переступают, а ролик объявляют устаревшим.
- **Обвес** — не-код внутри пакета: профиль субтитров, виды, шрифты,
  веса детектора, инструкции модели, страница экрана (`vertcut/assets/`).
- **Сессия** — одна рабочая сессия разработки с ИИ-помощником; номера
  идут по порядку, «решение 14-й сессии» значит «когда принято».

## Откуда взялось

Форк **по механике, а не по коду** соседнего сервиса «Нарезатор»:
механика перенесена КОПИЕЙ. **Ничего не импортируется ни из Нарезатора,
ни из его библиотеки** — одолженное окружение мешает раздавать сервис;
есть автотест. Всё «про канал автора» (эталоны, шрифт, фоны, обложки)
не перенесено.

## Главное решение

**Видео разбирается один раз, ролики режутся много раз.** Разбор дорогой
(~9 мин на 20 мин видео), нарезка дешёвая. Стадии читают диск, пишут
диск и завершаются; общего процесса с состоянием нет, базы нет — всё
состояние в файлах.

- **Три места на машине:** программа (удалил — и всё), настройки
  (переживают переустановку), разборы (работа человека, не трогается ничем).
- **Пути собираются только в `vertcut/layout.py`** — есть автотест.
- **Корень перебивается `VERTCUT_HOME`;** проверки работают в песочнице,
  никогда на живой папке человека. Переменная меняет и папку настроек
  (`$VERTCUT_HOME/.settings`).
- **Имена файлов в репозитории — латиницей**, слова в коде русские
  (`from . import intake as приём`): русские имена ломаются у получателя
  архива. **Исключение — скрипты, которые едут в архивах**
  (`install/installer.py`, `progress.py`, `sources.txt`, `.sh`, `.ps1`)
  и `ORIGIN.md` в пакете: английские целиком, с именами, — человек
  открывает их, чтобы понять, что делает неподписанная программа.
- **Всё, что видит человек, — по-английски**, по словарю
  `docs/glossary.md`: экран, ошибки и подсказки, ход работы, команда
  и её ключи, установка, адреса экранов, профиль и виды, инструкции
  модели, имена папок и файлов на его машине. Русскими остаются имена
  в коде, ключи json между сервером и страницей, классы `.в-…`,
  примечания и `docs/` — их видит только разработчик. Перевод
  закончен (23-я сессия); новая русская строка для человека — красный
  тест `tests/test_english.py`; то, что едет к человеку переменной
  или с диска, ловит прочёс `tools/cyrillic-sweep.py`. Исключения —
  только явным списком: пути `/апи/`, `/файлы/`, `/шрифты/` и пометки
  `не для человека` (с причиной) и `язык видео` — для строки про язык
  ВИДЕО, который не трогается.
- **Обвес лежит внутри пакета** — иначе не попадает в поставку; есть
  проверка, что каждый файл обвеса описан в поставке.

Ключи — английские, по словарю; старых русских команда не принимает.
Каждый ключ, названный в подсказке где угодно в проекте, сверяется
с тем, что команда принимает, — есть автотест.

**`videos`, `phrases` и `cuts` не трогают тяжёлых библиотек.** Они
читают голый json. Это ровно тот момент, когда с окружением может быть
что-то не так, а человеку надо посмотреть, что у него разобрано.

## Стадии разбора

```
extract → hear → align → shots → crop
дорожка   слух    укладка  склейки  рамки
```

- Каждая стадия ставит штамп и переступается, а не переделывается.
- **У укладки есть отпечаток** (текст, правила укладки, правила нарезки
  фраз — числа И код правил): поменяли правило — стадия не сделана.
  У распознавания отпечатка нет — его стережёт отпечаток исходника.
- Сценарий есть — текстом берётся он; нет — расшифровка из тех же слов,
  у которых измерены времена (`transcript.txt`, а не `script.txt`).
- Отпечаток исходника проверяется на входе: подменили файл — падаем.

## Устройство, которое легко сломать

- **Границы и ключ ролика — в номерах СЛОВ**, не фраз и не секунд:
  перенарезка фраз перенумеровывает их. Правки фраз тоже на номерах слов.
- **Фразы режутся без оглядки на стиль** (знаки, паузы, длительность);
  «влезает ли в строку» считает рисование субтитра настоящим шрифтом.
- **Сборка — одна цепочка ffmpeg, одно кодирование.** Шкалу ролика
  считает только `plans.карта()`/`plans.timeline`; времена сбрасываются
  явно `setpts=PTS-STARTPTS`; пороги в цепочке — посреди между кадрами;
  отрезки — `gte*lt`, не `between`. `-t` только у выхода.
- **Профиль субтитров — четыре уровня:** поставляемый → личный → копия
  в видео (заводится сразу при разборе) → свой у вертикалки (только если
  её правили). Правка числом правит ТЕКСТ yaml, сохраняя примечания;
  незнакомый ключ — отказ. Ключи английские; у файла есть `version`,
  без неё — старый образец: отказ словами, переезда нет.
- **Плашка в конце выключена по умолчанию** и замещает картинку, не
  удлиняя файл; выключенная не оставляет следа (файл совпадает побайтово).
- **Субтитры в файле можно выключить — и это не стиль.** Решение лежит
  у видео (`meta.json`, по галочке настроек при ПЕРВОМ разборе) и у
  вертикалки (`cut.json`, если решила иначе); спрашивать — только
  `subs.в_файле`. Выключенные: нет слоя и входа в цепочке, заслон
  «Subtitles» пропущен, а не провален, штамп помнит `субтитры`.
- **Пять заслонов** сборки: длина, кадр против кадра, края и стыки,
  субтитр, плашка. Штамп «готово» — только после сверки. Пороги чужой
  работы не смягчаются ради новой.
- **Штамп сборки помнит, из чего собран файл:** фразы, профиль ЭТОЙ
  вертикалки, монтаж, нумерацию планов, плашку (спрашивается первой).
  Неизвестность — значит «устарел».
- **Очередь и долгая работа — файлы** (`works.py`, один механизм):
  хозяин по номеру процесса, своя группа процессов, «остановить» — сигнал.
  «Собрать» у одной вертикалки собирает одну.
- **Модель — приправа:** без ключа работает всё. Одна функция
  `ai.спросить`, сеть только в `ai.py`, цену не знаем — денег
  не показываем, ответ ложится на диск до разбора, двойное нажатие
  не оплачивается дважды. Правки модели к субтитрам — только
  предложение: ложатся обычной правкой рукой, когда человек принял.

## Экран

- **Веб-слой только переводит:** просьба → вызов существующей функции →
  json. Логики, порогов и арифметики времени в нём нет — есть автотест.
- **Браузер не рисует субтитр** и плашку: кадр — картинки с сервера,
  нарисованные тем же кодом, что и файл. `.vc-sub` не используется.
- **Слушает `127.0.0.1` + пропуск на запуск** (заголовок
  `X-Vertcut-Pass` или адрес `?pass=`) + проверка хозяина и `Origin`.
  Без пропуска отвечает только `/апи/здоровье` (список `БЕЗ_ПРОПУСКА`).
- Сервер — стандартная библиотека; страница без сборки (никакого node).
- `tokens.css` и `components.css` — копия пакета дизайна байт в байт;
  своё — в `screen.css`. Свои классы — русскими именами (`.в-…`); каждое
  своё имя `vc-` записано в `docs/decisions.md` — есть автотест.
- Экраны в адресе: `#videos`, `#analysis/{слаг}`, `#segments/…`,
  `#clip/…`, `#subtitles/…`, `#descriptions/…`, `#export/…`,
  `#settings[/раздел]`, `#help`. Пути ручек (`/апи/…`) и ключи json
  остаются русскими: человек их не видит, а на `/апи/здоровье` держится
  внешний значок в строке меню (программа вне репозитория).
- Адрес после `#` читают и пишут только в `js/route.js`; вкладку
  открывает только `server.открыть_в_браузере` (адрес — аргументом).
- Быстрые правки с экрана несут **отметку файла** (`web/mark.py`):
  файл поменяли из терминала — отказ, а не тихая перезапись.
- **Выход — одна функция на двоих** (`server.выключить`): кнопка
  «Quit Vertcut» последней строкой подвала колонки и `vertcut stop`,
  который стучится той же ручкой; сигнал — только запасом. Долгая
  работа не обрывается, и страница говорит это ДО нажатия.
  Внешний значок в строке меню гасит сервис сигналом по номеру
  из `app.json`, как раньше; формат `app.json` не меняется.
- Экран ничего не помнит: всё читается с диска в момент показа.
  Перерисовка не теряет прокрутку, раскрытое и фокус; ничто не меняет
  высоту от действий человека.

## Правила работы

- **ffmpeg — только через `run.py`**: своя копия лежит не в PATH.
- **Перед любым текстом для человека — сверься со словарём**
  `docs/glossary.md`; нового понятия там нет — сперва впиши его.
- **Числа — в `vertcut/tuning.py`, с происхождением.** Это отправные
  точки с одного канала, а не замеры на чужом материале. Одно число —
  одно место.
- **Число, которое можно померить, меряется**; замер, который придётся
  повторять, заводится командой сервиса, а не черновым скриптом.
- **Унаследованное правило проверяется, а не переписывается** (так
  не устояли «`-ss` сбрасывает время» и порог склеек 45).
- **Никаких заглушек, молча возвращающих пустоту** — падать словами.
- **Мёртвых кнопок не рисуется.** Подпись кнопки не переносится.
- **Зависимости не ставятся сами** — нужна новая, сказать автору.
- **Версии библиотек — только из `constraints.txt`** (`-c`): установщик,
  README, сборочные машины. Свежие проверяет еженедельная проверка
  без файла; обновлять файл — когда она зелёная.
- **Проверять тем способом, каким запускает человек:** двойной щелчок
  даёт урезанный PATH и другую архитектуру; на Windows — сборочная машина.
  Плюс сквозной прогон на настоящем видео: зелёные тесты не доказывают,
  что жива цепочка ffmpeg. Что видно глазами — глазами и ловится.
- **Команды установки в README и `INSTALL.md` — одни и те же**,
  и сборочные машины Windows и Linux берут их из README
  (`tools/doc-commands.py`): меняешь путь установки — меняй оба
  документа, есть автотест. `INSTALL.md` обещает только проверенное.
- **Русские буквы рассыпаются у чужого разборщика** (заголовки HTTP,
  адреса, AppleScript, `tar`, вывод в трубу на Windows…): передавать
  их аргументом или байтами. Тринадцать мест — в `docs/decisions.md`.
- **Вопрос к системе бывает не вопросом:** `os.kill(pid, 0)` на Windows
  убивает — спрашивать через `works.жив`.
- **Запись в документ — не починка:** сперва убрать неудобство, писать
  только про то, что убрать нельзя.
- **Ход работы печатается со сбросом буфера** (`report.py`).
- **Перед выпуском — прочёс** `python tools/cyrillic-sweep.py`: заслон
  смотрит код, прочёс — то, что человек получил (экран, команда, диск,
  архив). Окон на столе он не открывает: `osascript` и `open` — заглушки.
- **Времянка — своя на каждый вызов и рядом с целью** (`media.кадр_в_файл`).
- **Кэш в долгоживущем сервисе помнится вместе с отметкой файла.**
- **Одно слово — один смысл** в ответах ручек (`хвост` уже занят журналом).
- **То, что уезжает к человеку, проверяется глазами системы**
  (`codesign --verify`, `syspolicy_check`, имена в архиве как их увидит
  получатель).
